## Definición de MVP

### ¿Qué es el MVP de BoliviaExperience?

El MVP (Minimum Viable Product) es la versión más pequeña del producto que permite validar las hipótesis fundamentales de negocio con el menor esfuerzo posible.

**NO es:** Un producto incompleto o una demo.
**SÍ es:** Un producto funcional que resuelve el problema core para un segmento específico y permite medir comportamiento real.

## Criterios de Validación por Hipótesis

### Matriz de Decisión Post-MVP

| Escenario | Resultado | Decisión | Acción |
|-----------|-----------|----------|--------|
| **Éxito total** | Todas las hipótesis principales validadas | **Perseverar** | Escalar marketing, agregar features, buscar inversión |
| **Éxito parcial** | 50-70% hipótesis validadas | **Iterar** | Ajustar features que no funcionaron, mantener las que sí |
| **Pivotaje suave** | Una hipótesis fundamental falla | **Pivotar** | Cambiar segmento, modelo de negocio o propuesta de valor |
| **Pivotaje radical** | Múltiples hipótesis fundamentales fallan | **Reevaluar** | Considerar si el problema vale la pena resolver |
| **Fracaso** | <30% hipótesis validadas | **Parar** | Evaluar learnings, decidir si continuar o cerrar |

### Criterios Específicos de Validación

#### Para Continuar (Perseverar)
- [ ] ≥3 sesiones por turista durante estadía
- [ ] ≥25% retención a 7 días
- [ ] ≥50% sesiones con interacción en mapa
- [ ] ≥30% usuarios con al menos 1 favorito
- [ ] ≥15% usuarios que califican al menos 1 lugar
- [ ] ≥60% uso de categorías vs búsqueda directa
- [ ] NPS ≥30
- [ ] Rating stores ≥4.0

#### Para Iterar
- [ ] 2-3 sesiones por turista
- [ ] 15-25% retención D7
- [ ] 30-50% interacción con mapa
- [ ] 15-30% usuarios con favoritos
- [ ] 5-15% usuarios que califican
- [ ] 40-60% uso de categorías
- [ ] NPS 20-30
- [ ] Rating stores 3.5-4.0

#### Para Pivotar
- [ ] <2 sesiones por turista
- [ ] <15% retención D7
- [ ] <30% interacción con mapa
- [ ] <15% usuarios con favoritos
- [ ] <5% usuarios que califican
- [ ] <40% uso de categorías
- [ ] NPS <20
- [ ] Rating stores <3.5

## ADR-007: Definición y Alcance del MVP

**Fecha:** 2026-06-26
**Estado:** Aceptado

**Contexto:**
El prompt maestro define un alcance muy amplio que incluye múltiples plataformas y funcionalidades. El presupuesto y tiempo son limitados.

**Opciones consideradas:**
- Opción A — MVP completo según prompt maestro
  · Ventajas: Producto completo desde el inicio
  · Desventajas: 6+ meses de desarrollo, $50K+ presupuesto
- Opción B — MVP reducido (solo app móvil core)
  · Ventajas: 2-3 meses, $20-30K, validación rápida
  · Desventajas: Sin panel admin/empresa completo
- Opción C — MVP mínimo (solo browsing, sin opiniones)
  · Ventajas: 1-2 meses, validación más rápida
  · Desventajas: Sin engagement, métricas limitadas

**Decisión:**
Opción B — MVP reducido:
- App móvil: Home, mapa, categorías, fichas, búsqueda, favoritos, opiniones básicas, perfil
- Backend: API core (lugares, categorías, opiniones, favoritos, usuarios)
- Panel admin: CRUD lugares y usuarios (básico)
- Panel empresa: Edición de perfil (básico)
- Excluido: Filtros avanzados, eventos, clima, notificaciones, panels completos

**Consecuencias:**
- Positivas: Lanzamiento en 2-3 meses, Within presupuesto
- Negativas: Algunas features post-MVP
- Deuda técnica: Posible refactorización al agregar features

**Revisión:** Revisar después del launch y primeros datos.
