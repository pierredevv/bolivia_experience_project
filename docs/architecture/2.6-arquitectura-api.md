## Convenciones de la API

### Nombres de Recursos

- **Plural**: `/places`, `/users`, `/reviews`
- **Lowercase**: `/place-photos`, no `/PlacePhotos`
- **Snake case**: `/search_history`, no `/searchHistory`

### HTTP Methods

| Método | Uso | Idempotente |
|--------|-----|-------------|
| GET | Leer recursos | Sí |
| POST | Crear recursos | No |
| PUT | Actualizar recurso completo | Sí |
| PATCH | Actualizar parcialmente | Sí |
| DELETE | Eliminar recurso | Sí |

### Headers Requeridos

```
Content-Type: application/json
Authorization: Bearer <access_token>
Accept-Language: es | en
X-Request-ID: <uuid> (para tracking)
```

### Headers de Respuesta

```
Content-Type: application/json
X-Request-ID: <uuid>
X-RateLimit-Limit: 100
X-RateLimit-Remaining: 95
X-RateLimit-Reset: 1687757700
```

### Paginación

```
GET /api/v1/places?page=1&per_page=20&sort=rating_avg&order=desc
```

| Parámetro | Tipo | Default | Descripción |
|-----------|------|---------|-------------|
| page | integer | 1 | Número de página |
| per_page | integer | 20 | Elementos por página (max: 100) |
| sort | string | created_at | Campo de ordenamiento |
| order | string | desc | asc o desc |

### Filtros

```
GET /api/v1/places?category=restaurantes&rating_min=4&is_open=true
```

| Filtro | Tipo | Descripción |
|--------|------|-------------|
| category | string | Slug de categoría |
| rating_min | number | Calificación mínima |
| rating_max | number | Calificación máxima |
| is_featured | boolean | Solo destacados |
| is_open | boolean | Abierto ahora |
| latitude | number | Latitud para búsqueda cercana |
| longitude | number | Longitud para búsqueda cercana |
| radius | number | Radio en metros (default: 5000) |

## ADR-224: Arquitectura de la API

**Fecha:** 2026-06-26
**Estado:** Aceptado

**Contexto:**
Definir los estándares y convenciones para la API REST del backend.

**Opciones consideradas:**
- Opción A — RESTful API con versionado URL
  · Ventajas: Simple, estándar, fácil de consumir
  · Desventajas: proliferación de versiones
- Opción B — GraphQL
  · Ventajas: Flexible, exactamente los datos que se necesitan
  · Desventajas: Más complejo, caching más difícil, overkill para MVP
- Opción C — gRPC
  · Ventajas: Rápido, tipado, efficiente
  · Desventajas: Menos compatible con navegadores, más complejo

**Decisión:**
Opción A — RESTful API con versionado URL (/api/v1/).

**Justificación:**
1. **Estándar de la industria**: todas las APIs modernas son REST
2. **Simplicidad**: fácil de consumir desde Flutter, React, y cualquier cliente
3. **Documentación**: Swagger/OpenAPI se genera automáticamente
4. **Caching**: HTTP caching nativo (ETags, Cache-Control)
5. **Herramientas**: Postman, curl, navegadores funcionan directamente

**Consecuencias:**
- Positivas: Simple, estándar, bien documentada
- Negativas: Puede requerir múltiples versiones en el futuro
- Deuda técnica: Posible migración a GraphQL si se requiere más flexibilidad

**Revisión:** Revisar después de 12 meses. Evaluar si GraphQL es necesario.

## Ejemplo de Implementación NestJS

```typescript
// places.controller.ts
@Controller('api/v1/places')
export class PlacesController {
  constructor(private readonly placesService: PlacesService) {}

  @Get()
  @ApiOperation({ summary: 'List places with filters' })
  @ApiQuery({ name: 'category', required: false })
  @ApiQuery({ name: 'rating_min', required: false })
  @ApiQuery({ name: 'latitude', required: false })
  @ApiQuery({ name: 'longitude', required: false })
  @ApiQuery({ name: 'radius', required: false })
  @ApiQuery({ name: 'page', required: false })
  @ApiQuery({ name: 'per_page', required: false })
  async findAll(
    @Query() query: FilterPlacesDto,
  ): Promise<PaginatedResponseDto<PlaceDto>> {
    return this.placesService.findAll(query);
  }

  @Get(':id')
  @ApiOperation({ summary: 'Get place by ID' })
  @ApiParam({ name: 'id', type: 'string' })
  async findOne(@Param('id', ParseUUIDPipe) id: string): Promise<PlaceDto> {
    return this.placesService.findOne(id);
  }

  @Post()
  @UseGuards(AuthGuard, RolesGuard)
  @Roles('admin')
  @ApiOperation({ summary: 'Create a new place' })
  async create(@Body() createPlaceDto: CreatePlaceDto): Promise<PlaceDto> {
    return this.placesService.create(createPlaceDto);
  }
}
```
