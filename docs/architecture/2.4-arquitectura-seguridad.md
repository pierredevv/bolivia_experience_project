## Rate Limiting

### Configuración

| Endpoint | Límite por IP | Límite por usuario | Ventana |
|----------|---------------|-------------------|---------|
| POST /auth/login | 5 requests | — | 15 min |
| POST /auth/register | 3 requests | — | 1 hora |
| POST /auth/refresh | 10 requests | 20 requests | 15 min |
| GET /places | 100 requests | 200 requests | 1 min |
| GET /places/:id | 100 requests | 200 requests | 1 min |
| POST /reviews | 10 requests | 5 requests | 1 hora |
| GET /search | 50 requests | 100 requests | 1 min |
| GET /weather | 20 requests | 30 requests | 1 min |

### Implementación

```typescript
// Ejemplo: Rate Limiting en NestJS
@Injectable()
export class RateLimiterGuard implements CanActivate {
  constructor(private readonly redisService: RedisService) {}

  async canActivate(context: ExecutionContext): Promise<boolean> {
    const request = context.switchToHttp().getRequest();
    const ip = request.ip;
    const userId = request.user?.id;
    const key = userId ? `rate:${userId}` : `rate:${ip}`;
    
    const current = await this.redisService.incr(key);
    if (current === 1) {
      await this.redisService.expire(key, 60); // 1 minuto
    }
    
    if (current > 100) { // Límite por minuto
      throw new HttpException('Too many requests', HttpStatus.TOO_MANY_REQUESTS);
    }
    
    return true;
  }
}
```

## Protección contra Ataques

### OWASP Top 10 — Mitigaciones

| Ataque | Mitigación | Implementación |
|--------|-----------|----------------|
| **A01: Broken Access Control** | RBAC + Authorization Guards | NestJS Guards + Roles decorators |
| **A02: Cryptographic Failures** | TLS 1.3 + Encryption at rest | GCP managed SSL + Cloud SQL encryption |
| **A03: Injection** | Input validation + Prisma ORM | class-validator + Prisma parameterized queries |
| **A04: Insecure Design** | Threat modeling + Secure design | ADR-222, code reviews |
| **A05: Security Misconfiguration** | Security headers + Hardening | Helmet + Nginx config |
| **A06: Vulnerable Components** | Dependency scanning | GitHub Dependabot + npm audit |
| **A07: Auth Failures** | Rate limiting + Account lockout | Redis rate limiter + brute force protection |
| **A08: Data Integrity** | JWT signing + Input validation | RS256 + class-validator |
| **A09: Logging Failures** | Audit logging | Winston + Cloud Logging |
| **A10: SSRF** | Input validation + Allowlist | URL validation + IP restrictions |

### SQL Injection — Protección

```typescript
// Prisma parameterized queries (protección automática)
const places = await prisma.place.findMany({
  where: {
    name: { contains: userInput }, // Prisma usa parameterized queries
  },
});

// Raw queries (requiere sanitización manual)
const places = await prisma.$queryRaw`
  SELECT * FROM places 
  WHERE name ILIKE ${'%' + sanitize(userInput) + '%'}
`;
```

### Implementación

```typescript
// Audit interceptor
@Injectable()
export class AuditInterceptor implements NestInterceptor {
  constructor(private readonly auditService: AuditService) {}

  intercept(context: ExecutionContext, next: CallHandler): Observable<any> {
    const request = context.switchToHttp().getRequest();
    const { method, url, ip, user } = request;
    const startTime = Date.now();

    return next.handle().pipe(
      tap(() => {
        const duration = Date.now() - startTime;
        this.auditService.log({
          method,
          url,
          ip,
          userId: user?.id,
          duration,
          timestamp: new Date(),
        });
      }),
    );
  }
}
```

## ADR-222: Estrategia de Seguridad

**Fecha:** 2026-06-26
**Estado:** Aceptado

**Contexto:**
Definir las medidas de seguridad para proteger datos de usuarios, negocios y del sistema.

**Opciones consideradas:**
- Opción A — Seguridad mínima (solo HTTPS + auth)
  · Ventajas: Rápido de implementar
  · Desventajas: Vulnerable a múltiples ataques
- Opción B — Seguridad completa (OWASP Top 10 + Defense in Depth)
  · Ventajas: Protección robusta, cumple estándares
  · Desventajas: Más tiempo de desarrollo, complejidad adicional
- Opción C — Seguridad basada en riesgos (priorizar por impacto)
  · Ventajas: Balance entre seguridad y velocidad
  · Desventajas: Requiere análisis de riesgos continuo

**Decisión:**
Opción B — Seguridad completa siguiendo OWASP Top 10:
- Defense in Depth (4 capas)
- JWT con refresh token rotation
- RBAC con 3 roles
- Rate limiting por IP y usuario
- Headers de seguridad HTTP
- Secret Manager para credenciales
- Audit logging

**Consecuencias:**
- Positivas: Protección robusta, cumple estándares internacionales
- Negativas: Más tiempo de desarrollo (~10% adicional)
- Deuda técnica: Ninguna significativa

**Revisión:** Revisar después de 6 meses. Evaluar penetration testing.
