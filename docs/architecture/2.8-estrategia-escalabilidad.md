## ADR-225: Estrategia de Escalabilidad

**Fecha:** 2026-06-26
**Estado:** Aceptado

**Contexto:**
Definir cómo escalar el sistema desde 100 hasta 1,000,000 usuarios.

**Opciones consideradas:**
- Opción A — Escalar verticalmente (bigger machine)
  · Ventajas: Simple, sin cambios de arquitectura
  · Desventajas: Limitado, costos exponenciales
- Opción B — Escalar horizontalmente (more machines)
  · Ventajas: Escalable ilimitado, costos lineales
  · Desventajas: Requiere arquitectura stateless, más complejo
- Opción C — Estrategia híbrida (vertical + horizontal según nivel)
  · Ventajas: Balance entre simplicidad y escalabilidad
  · Desventajas: Requiere planificación por niveles

**Decisión:**
Opción C — Estrategia híbrida por niveles:
- Nivel 1-2: Escalado vertical (Cloud Run auto-scale)
- Nivel 3: Escalado horizontal + Load Balancer
- Nivel 4: Microservicios + sharding
- Nivel 5: Multi-región + global distribution

**Consecuencias:**
- Positivas: Escalabilidad progresiva, costos controlados
- Negativas: Requiere re-arquitectura en niveles 4-5
- Deuda técnica: Posible rework al migrar a microservicios

**Revisión:** Revisar al alcanzar cada nivel. Evaluar si se necesita escalar.
