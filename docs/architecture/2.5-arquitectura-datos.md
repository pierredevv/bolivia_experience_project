## Modelo Físico (Tablas PostgreSQL)

### Users Table

```sql
CREATE TABLE users (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    email VARCHAR(255) UNIQUE NOT NULL,
    name VARCHAR(255) NOT NULL,
    photo_url TEXT,
    country VARCHAR(100),
    language VARCHAR(5) DEFAULT 'es',
    role VARCHAR(20) DEFAULT 'usuario' CHECK (role IN ('admin', 'empresa', 'usuario')),
    firebase_uid VARCHAR(255) UNIQUE,
    is_active BOOLEAN DEFAULT true,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- Índices
CREATE INDEX idx_users_email ON users(email);
CREATE INDEX idx_users_firebase_uid ON users(firebase_uid);
CREATE INDEX idx_users_role ON users(role);
```

### Categories Table

```sql
CREATE TABLE categories (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name VARCHAR(100) NOT NULL,
    name_en VARCHAR(100) NOT NULL,
    icon VARCHAR(50) NOT NULL,
    slug VARCHAR(100) UNIQUE NOT NULL,
    description TEXT,
    description_en TEXT,
    display_order INTEGER DEFAULT 0,
    is_active BOOLEAN DEFAULT true,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- Índices
CREATE INDEX idx_categories_slug ON categories(slug);
```

### Places Table

```sql
CREATE TABLE places (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name VARCHAR(255) NOT NULL,
    description TEXT,
    description_en TEXT,
    address VARCHAR(500) NOT NULL,
    phone VARCHAR(50),
    website VARCHAR(255),
    instagram VARCHAR(255),
    facebook VARCHAR(255),
    tiktok VARCHAR(255),
    latitude DECIMAL(10, 8) NOT NULL,
    longitude DECIMAL(11, 8) NOT NULL,
    location GEOGRAPHY(POINT, 4326) GENERATED ALWAYS AS (
        ST_SetSRID(ST_MakePoint(longitude, latitude), 4326)
    ) STORED,
    rating_avg DECIMAL(3, 2) DEFAULT 0,
    rating_count INTEGER DEFAULT 0,
    category_id UUID NOT NULL REFERENCES categories(id),
    owner_id UUID REFERENCES users(id),
    is_featured BOOLEAN DEFAULT false,
    is_active BOOLEAN DEFAULT true,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

-- Índices
CREATE INDEX idx_places_category ON places(category_id);
CREATE INDEX idx_places_owner ON places(owner_id);
CREATE INDEX idx_places_location ON places USING GIST(location);
CREATE INDEX idx_places_rating ON places(rating_avg DESC);
CREATE INDEX idx_places_featured ON places(is_featured) WHERE is_featured = true;
CREATE INDEX idx_places_active ON places(is_active) WHERE is_active = true;
```

### Place Photos Table

```sql
CREATE TABLE place_photos (

CREATE INDEX idx_place_photos_place ON place_photos(place_id);
```

### Reviews Table

```sql
CREATE TABLE reviews (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    user_id UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE,
    place_id UUID NOT NULL REFERENCES places(id) ON DELETE CASCADE,
    rating INTEGER NOT NULL CHECK (rating >= 1 AND rating <= 5),
    comment TEXT,
    photos TEXT[], -- Array de URLs de fotos
    visit_date DATE,
    is_approved BOOLEAN DEFAULT false,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    updated_at TIMESTAMP WITH TIME ZONE DEFAULT NOW(),
    
    -- Un usuario solo puede tener 1 review por lugar
    UNIQUE(user_id, place_id)
);

-- Índices
CREATE INDEX idx_reviews_place ON reviews(place_id);
CREATE INDEX idx_reviews_user ON reviews(user_id);
CREATE INDEX idx_reviews_rating ON reviews(rating);
CREATE INDEX idx_reviews_approved ON reviews(is_approved) WHERE is_approved = true;
```

## Consultas Geoespaciales Críticas

### 1. Buscar lugares dentro de un radio

```sql
-- Buscar lugares dentro de un radio de 5km desde una ubicación
SELECT 
    p.id,
    p.name,
    p.address,
    p.rating_avg,
    c.name as category_name,
    ST_Distance(
        p.location::geography,
        ST_SetSRID(ST_MakePoint(-17.7833, -18.1667), 4326)::geography
    ) as distance_meters
FROM places p
JOIN categories c ON p.category_id = c.id
WHERE ST_DWithin(
    p.location::geography,
    ST_SetSRID(ST_MakePoint(-17.7833, -18.1667), 4326)::geography,
    5000 -- 5 km en metros
)
AND p.is_active = true
ORDER BY distance_meters ASC
LIMIT 20;
```

### 2. Buscar lugares por categoría en un área

```sql
-- Buscar restaurantes en un radio de 3km
SELECT 
    p.*,
    ST_Distance(
        p.location::geography,
        ST_SetSRID(ST_MakePoint($1, $2), 4326)::geography
    ) as distance_meters
FROM places p
WHERE p.category_id = $3 -- ID de categoría "Restaurantes"
AND ST_DWithin(
    p.location::geography,
    ST_SetSRID(ST_MakePoint($1, $2), 4326)::geography,
    3000
)
AND p.is_active = true
ORDER BY distance_meters ASC;
```

### 3. Cluster de marcadores en el mapa

```sql
-- Agrupar lugares en clusters para el mapa (zoom level bajo)
SELECT 
    ST_ClusterDBSCAN(location, eps := 0.01, minpoints := 3) OVER () as cluster_id,
    COUNT(*) as cluster_count,
    AVG(latitude) as avg_lat,
    AVG(longitude) as avg_lng
FROM places
WHERE is_active = true
GROUP BY cluster_id;
```

### 4. Lugares cercanos a un punto (para "Cerca de Ti")

```sql
-- Top 10 lugares más cercanos con información completa
SELECT 
    p.id,
    p.name,
    p.description,
    p.address,
    p.phone,
    p.rating_avg,
    p.rating_count,
    c.name as category_name,
    c.icon as category_icon,
    (
        SELECT url FROM place_photos 
        WHERE place_id = p.id 
        ORDER BY display_order 
        LIMIT 1
    ) as photo_url,
    ST_Distance(
        p.location::geography,
        ST_SetSRID(ST_MakePoint($1, $2), 4326)::geography
    ) as distance_meters
FROM places p
JOIN categories c ON p.category_id = c.id
WHERE ST_DWithin(
    p.location::geography,
    ST_SetSRID(ST_MakePoint($1, $2), 4326)::geography,
    10000 -- 10 km
)
AND p.is_active = true
ORDER BY distance_meters ASC
LIMIT 10;
```

### Políticas de Caché

| Tipo de Dato | TTL | Estrategia Invalidación |
|-------------|-----|------------------------|
| Categorías | 24 horas | Manual (raro cambio) |
| Lugares destacados | 1 hora | Al editar lugar |
| Lugares por categoría | 30 min | Al agregar/eliminar lugar |
| Búsquedas | 5 min | TTL-based |

## Backup y Recuperación

### Estrategia de Backups

| Tipo | Frecuencia | Retención | Almacenamiento |
|------|-----------|-----------|----------------|
| Backup completo | Diario (2:00 AM UTC) | 30 días | Cloud Storage (región us-central1) |

| Escenario | RPO (Recovery Point) | RTO (Recovery Time) | Procedimiento |
|-----------|---------------------|---------------------|---------------|

## ADR-223: Estrategia de Datos

**Fecha:** 2026-06-26
**Estado:** Aceptado

**Contexto:**
Definir cómo se almacenan, cachean y respaldan los datos del sistema.

**Opciones consideradas:**
- Opción A — PostgreSQL puro (sin caché)
  · Ventajas: Simple, consistente
  · Desventajas: Lento para consultas frecuentes, carga en DB
- Opción B — PostgreSQL + Redis cache
  · Ventajas: Rápido,减轻 carga de DB
  · Desventajas: Consistencia eventual, complejidad adicional
- Opción C — PostgreSQL + Firestore cache
  · Ventajas: Integrado con Firebase, serverless
  · Desventajas: Vendor lock-in, costos impredecibles

**Decisión:**
Opción C — PostgreSQL + Firestore cache (para MVP):
- PostgreSQL como source of truth
- Firestore como caché para datos estáticos (categorías, lugares destacados)
- Caché en el cliente (Hive) para offline básico

**Consecuencias:**
- Positivas: Rendimiento mejorado, integración con Firebase
- Negativas: Consistencia eventual, vendor lock-in parcial
- Deuda técnica: Posible migración a Redis si se requiere más control

**Revisión:** Revisar después de 6 meses. Evaluar consistencia y rendimiento.
