## 2. Tipos de Backup

### 2.1 Backup Completo (Full Dump)

**Qué:** Copia completa de la base de datos.
**Cuándo:** Diariamente a las 02:00 UTC (hora de menor tráfico).
**Dónde:** Cloud Storage (bucket: `bolivia-experience-backups`).

#### Configuración Cloud SQL

```bash
# Crear backup manual
gcloud sql backups create \
    --instance=bolivia-experience-db \
    --description="Daily backup $(date +%Y%m%d)"

# Listar backups
gcloud sql backups list \
    --instance=bolivia-experience-db

# Programar backups automáticos (ya configurado por defecto en Cloud SQL)
gcloud sql instances patch bolivia-experience-db \
    --backup-start-time=02:00 \
    --enable-bin-log \
    --retained-backups-count=30
```

#### Script de Backup Manual (PostgreSQL directo)

```bash
#!/bin/bash
# scripts/backup-full.sh

set -e

DATE=$(date +%Y%m%d_%H%M%S)
BACKUP_DIR="/backups/full"
BACKUP_FILE="${BACKUP_DIR}/bolivia_experience_${DATE}.sql.gz"
GCS_BUCKET="gs://bolivia-experience-backups/full"

echo "🔄 Iniciando backup completo..."

# Crear directorio si no existe
mkdir -p ${BACKUP_DIR}

# Backup con pg_dump
pg_dump \
    --host=${DB_HOST} \
    --port=5432 \
    --username=${DB_USER} \
    --dbname=bolivia_experience \
    --format=custom \
    --compress=9 \
    --verbose \
    --file=${BACKUP_FILE}

# Verificar integridad
echo "✅ Backup creado: ${BACKUP_FILE}"
echo "📊 Tamaño: $(du -h ${BACKUP_FILE} | cut -f1)"

# Subir a Cloud Storage
echo "☁️  Subiendo a Cloud Storage..."
gsutil cp ${BACKUP_FILE} ${GCS_BUCKET}/

# Limpiar backups locales mayores a 7 días
find ${BACKUP_DIR} -name "*.sql.gz" -mtime +7 -delete

echo "🎉 Backup completado exitosamente"
```

### 2.2 Backup Incremental (WAL Archival)

**Qué:** Archivos Write-Ahead Log (WAL) que permiten point-in-time recovery.
**Cuándo:** Continuo (cada archivo WAL se archiva al completarse).
**Dónde:** Cloud Storage (bucket: `bolivia-experience-backups/wal`).

#### Configuración PostgreSQL (postgresql.conf)

```ini
# WAL Archival
archive_mode = on
archive_command = 'gsutil cp %p gs://bolivia-experience-backups/wal/%f'
archive_timeout = 300  # Forzar archivo WAL cada 5 minutos

# WAL Settings
wal_level = replica
max_wal_senders = 3
wal_keep_size = 1GB
```

#### Configuración Cloud SQL (GCP)

```bash
# Habilitar point-in-time recovery
gcloud sql instances patch bolivia-experience-db \
    --enable-bin-log \
    --retained-backups-count=7

# Cloud SQL maneja automáticamente el WAL archival
```

### 2.3 Snapshot de Cloud SQL

**Qué:** Snapshot del volumen de disco de la instancia.
**Cuándo:** Semanal (domingo a las 03:00 UTC).
**Dónde:** Cloud Storage (manejado por GCP).

```bash
# Crear snapshot manual
gcloud sql backups create \
    --instance=bolivia-experience-db \
    --description="Weekly snapshot $(date +%Y%m%d)"

# Programar snapshot semanal
gcloud sql instances patch bolivia-experience-db \
    --backup-start-time=03:00 \
    --retained-backups-count=4
```

## 3. Retención y Limpieza

### Política de Retención

| Tipo de Backup | Retención | Limpieza Automática |
|----------------|-----------|---------------------|
| Full dump diario | 30 días | Script cron |
| WAL archives | 7 días | GCS Lifecycle |
| Snapshot semanal | 4 semanas | Cloud SQL automático |

### Lifecycle Policy de Cloud Storage

```json
// gsutil lifecycle set lifecycle.json gs://bolivia-experience-backups
{
  "lifecycle": {
    "rule": [
      {
        "action": { "type": "Delete" },
        "condition": {
          "age": 30,
          "matchesPrefix": ["full/"]
        }
      },
      {
        "action": { "type": "Delete" },
        "condition": {
          "age": 7,
          "matchesPrefix": ["wal/"]
        }
      }
    ]
  }
}
```

### Script de Limpieza Local

```bash
#!/bin/bash
# scripts/cleanup-backups.sh

BACKUP_DIR="/backups"

echo "🧹 Limpiando backups antiguos..."

# Eliminar backups completos mayores a 7 días (locales)
find ${BACKUP_DIR}/full -name "*.sql.gz" -mtime +7 -delete
echo "✅ Backups completos locales > 7 días eliminados"

# Eliminar logs mayores a 30 días
find ${BACKUP_DIR}/logs -name "*.log" -mtime +30 -delete
echo "✅ Logs > 30 días eliminados"

# Reportar espacio
echo "📊 Espacio en disco:"
du -sh ${BACKUP_DIR}/*
```

## 4. Procedimientos de Recuperación

### 4.1 Escenario 1: Corrupción de Datos

**RPO:** 6 horas | **RTO:** 1 hora

```bash
#!/bin/bash
# scripts/restore-corruption.sh

# 1. Identificar el momento de corrupción
# Ejemplo: Datos corruptos detectados a las 15:00 del 2026-07-15

# 2. Restaurar desde backup completo más reciente
LATEST_BACKUP=$(gsutil ls gs://bolivia-experience-backups/full/ | sort | tail -1)

echo "📥 Restaurando desde: ${LATEST_BACKUP}"
gsutil cp ${LATEST_BACKUP} /tmp/restore.sql.gz

# 3. Crear DB temporal
createdb -h ${DB_HOST} -U ${DB_USER} bolivia_experience_restore

# 4. Restaurar
pg_restore \
    --host=${DB_HOST} \
    --port=5432 \
    --username=${DB_USER} \
    --dbname=bolivia_experience_restore \
    --verbose \
    --clean \
    /tmp/restore.sql.gz

# 5. Verificar integridad
psql -h ${DB_HOST} -U ${DB_USER} -d bolivia_experience_restore -c "
    SELECT 'users' as tabla, COUNT(*) FROM users
    UNION ALL
    SELECT 'places', COUNT(*) FROM places
    UNION ALL
    SELECT 'reviews', COUNT(*) FROM reviews;
"

# 6. Si todo está bien, renombrar
psql -h ${DB_HOST} -U ${DB_USER} -c "
    ALTER DATABASE bolivia_experience RENAME TO bolivia_experience_corrupt;
    ALTER DATABASE bolivia_experience_restore RENAME TO bolivia_experience;
"

echo "✅ Recuperación completada"
echo "⚠️  Datos entre el backup y la corrupción pueden estar perdidos"
```

### 4.2 Escenario 2: Fallo de Disco

**RPO:** 0 (WAL) | **RTO:** 15 minutos

```bash
# Cloud SQL maneja failover automáticamente

gcloud sql instances describe bolivia-experience-db

```

### 4.3 Escenario 3: Borrado Accidental

**RPO:** 6 horas | **RTO:** 30 minutos

```bash
#!/bin/bash
# scripts/restore-accidental-delete.sh

# Ejemplo: Tabla 'reviews' fue borrada accidentalmente

# 1. Detener la aplicación (si es posible)
echo "⚠️  Detenga la aplicación antes de continuar"
read -p "Presione Enter cuando la aplicación esté detenida..."

# 2. Restaurar solo la tabla afectada
BACKUP_FILE=$(gsutil ls gs://bolivia-experience-backups/full/ | sort | tail -1)
gsutil cp ${BACKUP_FILE} /tmp/restore.sql.gz

# 3. Extraer y restaurar solo la tabla
pg_restore \
    --host=${DB_HOST} \
    --port=5432 \
    --username=${DB_USER} \
    --dbname=bolivia_experience \
    --data-only \
    --table=reviews \
    /tmp/restore.sql.gz

# 4. Verificar
psql -h ${DB_HOST} -U ${DB_USER} -d bolivia_experience -c "
    SELECT COUNT(*) as total_reviews FROM reviews;
"

echo "✅ Tabla reviews restaurada"
```

### 4.4 Escenario 4: Point-in-Time Recovery

**RPO:** 5 minutos (WAL) | **RTO:** 30 minutos

```bash
#!/bin/bash
# scripts/restore-point-in-time.sh

# Ejemplo: Recuperar hasta 2026-07-15 14:30:00 UTC

TARGET_TIME="2026-07-15T14:30:00Z"

echo "🕐 Recuperando hasta: ${TARGET_TIME}"

# 1. Restaurar desde el último backup completo antes del TARGET_TIME
BACKUP_FILE="gs://bolivia-experience-backups/full/bolivia_experience_20260715_020000.sql.gz"
gsutil cp ${BACKUP_FILE} /tmp/restore.sql.gz

# 2. Crear DB temporal
createdb -h ${DB_HOST} -U ${DB_USER} bolivia_experience_pitr

# 3. Restaurar backup completo
pg_restore \
    --host=${DB_HOST} \
    --port=5432 \
    --username=${DB_USER} \
    --dbname=bolivia_experience_pitr \
    --clean \
    /tmp/restore.sql.gz

# 4. Aplicar WAL archives hasta TARGET_TIME
# (Cloud SQL maneja esto automáticamente con PITR)

# 5. Verificar
psql -h ${DB_HOST} -U ${DB_USER} -d bolivia_experience_pitr -c "
    SELECT MAX(created_at) as ultimo_registro FROM reviews;
"

echo "✅ Point-in-time recovery completado"
```

### 4.5 Escenario 5: Desastre Regional

**RPO:** 24 horas | **RTO:** 4 horas

```bash
#!/bin/bash
# scripts/restore-regional-disaster.sh

# 1. Crear nueva instancia en región alterna
gcloud sql instances create bolivia-experience-db-dr \
    --database-version=POSTGRES_15 \
    --region=southamerica-east1 \
    --tier=db-custom-2-8192 \
    --storage-size=20GB

# 2. Restaurar desde el último backup en Cloud Storage
BACKUP_FILE="gs://bolivia-experience-backups/full/bolivia_experience_20260715_020000.sql.gz"
gsutil cp ${BACKUP_FILE} /tmp/restore.sql.gz

# 3. Importar a la nueva instancia
gcloud sql import sql bolivia-experience-db-dr \
    /tmp/restore.sql.gz \
    --database=bolivia_experience

# 4. Actualizar variables de entorno de la aplicación
echo "⚠️  Actualice DATABASE_URL en su aplicación:"
echo "DATABASE_URL=postgresql://user:pass@new-host:5432/bolivia_experience"

# 5. Verificar
gcloud sql connect bolivia-experience-db-dr --user=postgres

echo "✅ Recuperación regional completada"
echo "⚠️  Puede haber pérdida de datos de las últimas 24 horas"
```

## 5. Verificación de Backups

### 5.1 Test de Restauración Semanal

```bash
#!/bin/bash
# scripts/test-restore.sh (ejecutar semanalmente)

set -e

echo "🧪 Iniciando test de restauración..."

# 1. Crear DB de prueba
TEST_DB="bolivia_experience_test_restore_$(date +%Y%m%d)"
createdb -h ${DB_HOST} -U ${DB_USER} ${TEST_DB}

# 2. Restaurar último backup
LATEST_BACKUP=$(gsutil ls gs://bolivia-experience-backups/full/ | sort | tail -1)
gsutil cp ${LATEST_BACKUP} /tmp/test_restore.sql.gz

pg_restore \
    --host=${DB_HOST} \
    --port=5432 \
    --username=${DB_USER} \
    --dbname=${TEST_DB} \
    --clean \
    /tmp/test_restore.sql.gz

# 3. Verificar integridad
echo "🔍 Verificando integridad..."
psql -h ${DB_HOST} -U ${DB_USER} -d ${TEST_DB} -c "
    -- Verificar tablas
    SELECT table_name, 
           (xpath('/row/cnt/text()', xml_count))[1]::text::int as row_count
    FROM (
        SELECT table_name, 
               query_to_xml('SELECT COUNT(*) as cnt FROM ' || table_name, false, true, '') as xml_count
        FROM information_schema.tables 
        WHERE table_schema = 'public' 
        AND table_type = 'BASE TABLE'
    ) t
    ORDER BY table_name;
"

# 4. Verificar datos críticos
psql -h ${DB_HOST} -U ${DB_USER} -d ${TEST_DB} -c "
    SELECT 
        'categories' as tabla,
        COUNT(*) as registros,
        MIN(created_at) as primer_registro,
        MAX(created_at) as ultimo_registro
    FROM categories
    UNION ALL
    SELECT 
        'places',
        COUNT(*),
        MIN(created_at),
        MAX(created_at)
    FROM places
    UNION ALL
    SELECT 
        'reviews',
        COUNT(*),
        MIN(created_at),
        MAX(created_at)
    FROM reviews;
"

# 5. Limpiar
dropdb -h ${DB_HOST} -U ${DB_USER} ${TEST_DB}

echo "✅ Test de restauración exitoso"
echo "📊 Backup verificado: ${LATEST_BACKUP}"
```

### 5.2 Checksum Verification

```bash
#!/bin/bash
# scripts/verify-backup-checksum.sh

BACKUP_FILE=$1

if [ -z "$BACKUP_FILE" ]; then
    echo "Uso: ./verify-backup-checksum.sh <backup_file.sql.gz>"
    exit 1
fi

echo "🔐 Verificando checksum..."

# Calcular checksum local
LOCAL_CHECKSUM=$(sha256sum ${BACKUP_FILE} | awk '{print $1}')

# Calcular checksum en GCS
GCS_CHECKSUM=$(gsutil hash -h ${BACKUP_FILE} | grep "Hash (SHA256)" | awk '{print $3}')

if [ "$LOCAL_CHECKSUM" = "$GCS_CHECKSUM" ]; then
    echo "✅ Checksum verificado correctamente"
    echo "   SHA256: ${LOCAL_CHECKSUM}"
else
    echo "❌ ERROR: Checksum no coincide"
    echo "   Local: ${LOCAL_CHECKSUM}"
    echo "   GCS:   ${GCS_CHECKSUM}"
    exit 1
fi
```

## 6. Monitoreo y Alertas

### 6.1 Métricas de Backup

| Métrica | Descripción | Alerta |
|---------|-------------|--------|
| Backup duration | Tiempo de ejecución | > 30 min |
| Backup size | Tamaño del backup | Variación > 50% |
| Last backup age | Tiempo desde último backup | > 26 horas |
| WAL lag | Retraso en archival WAL | > 1 hora |
| Restore test | Último test exitoso | > 7 días |

### 6.2 Alertas en GCP

```yaml
# monitoring/alerts.yaml

- name: backup-failed
  condition: >
    resource.type="cloudsql_database" AND
    metric.type="cloudsql.googleapis.com/database/backup/failed"
  notification_channels: ["email-admins", "slack-alerts"]
  
- name: backup-old
  condition: >
    resource.type="cloudsql_database" AND
    metric.type="cloudsql.googleapis.com/database/backup/age" AND
    value > 93600  # 26 horas en segundos
  notification_channels: ["email-admins"]

- name: wal-lag
  condition: >
    resource.type="cloudsql_database" AND
    metric.type="cloudsql.googleapis.com/database/replication/lag" AND
    value > 3600  # 1 hora en segundos
  notification_channels: ["email-admins", "slack-alerts"]
```
