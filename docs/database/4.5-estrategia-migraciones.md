## 1. Herramienta de Migraciones: Prisma Migrate

**Decisión:** Usar Prisma Migrate como herramienta principal de migraciones.

### Justificación

| Criterio | Prisma Migrate | Knex Migrate | TypeORM Migrate | Flyway |
|----------|---------------|--------------|-----------------|--------|
| Integración con ORM | ✅ Nativo | ❌ Externo | ✅ Nativo | ❌ Externo |
| Type safety | ✅ Schema.prisma | ❌ | ⚠️ Parcial | ❌ |
| Rollback | ⚠️ Manual | ✅ Nativo | ✅ Nativo | ✅ Nativo |
| Shadow DB | ✅ Automático | ❌ | ❌ | ❌ |
| DX (Developer Experience) | ✅ Excelente | ⚠️ Buena | ⚠️ Buena | ⚠️ Empresarial |
| Soporte PostGIS | ✅ Raw SQL | ✅ Nativo | ✅ Nativo | ✅ Nativo |

**Veredicto:** Prisma Migrate es la opción correcta porque ya usamos Prisma como ORM (ADR-205). La limitación de rollback se mitiga con el procedimiento manual documentado abajo.

## 3. Convenciones de Nombres de Migraciones

### Formato

```
YYYYMMDDHHMMSS_descriptive_name
```

### Ejemplos

| Migración | Descripción |
|-----------|-------------|
| `20260626120000_initial_schema` | Schema inicial (13 tablas) |
| `20260627100000_add_postgis_extension` | Extensión PostGIS |
| `20260628140000_add_place_hours_table` | Tabla de horarios |
| `20260629160000_add_review_replies` | Respuestas a reseñas |
| `20260701090000_add_notifications_table` | Sistema de notificaciones |

### Reglas

1. **Formato:** `YYYYMMDDHHMMSS_nombre_descriptivo` (generado automáticamente por Prisma)
2. **Idioma:** Inglés para nombres de migración
3. **Granularidad:** Una migración por cambio lógico (no mezclar add column + add table)
4. **Reversibilidad:** Cada migración debe ser documentada con su reverso manual

## 4. Manejo de Migraciones PostGIS

### Problema

Prisma no soporta tipos `geography` nativamente. La columna `location` se crea como `GENERATED ALWAYS AS` en PostgreSQL.

### Solución

Crear la migración inicial con SQL raw que incluya PostGIS:

```sql
-- migrations/20260626120000_initial_schema/migration.sql

-- Habilitar PostGIS
CREATE EXTENSION IF NOT EXISTS postgis;

-- ... (otras tablas via Prisma) ...

-- Tabla places con columna location generada
CREATE TABLE places (
    -- ... columnas normales via Prisma ...
    latitude DECIMAL(10, 8) NOT NULL,
    longitude DECIMAL(11, 8) NOT NULL,
    location GEOGRAPHY(POINT, 4326) GENERATED ALWAYS AS (
        ST_SetSRID(ST_MakePoint(longitude, latitude), 4326)
    ) STORED,
    -- ... resto de columnas ...
);

-- Índice GIST para PostGIS
CREATE INDEX idx_places_location ON places USING GIST(location);
```

### Procedimiento para Modificar Columnas PostGIS

1. Crear migración vacía: `npx prisma migrate dev --name update_postgis --create-only`
2. Editar el SQL manualmente para incluir cambios PostGIS
3. Aplicar: `npx prisma migrate dev`

## 5. Rollback de Migraciones

### Prisma NO soporta rollback automático

**Procedimiento manual de rollback:**

```bash
# 1. Conectar a la base de datos
psql $DATABASE_URL

# 2. Revertir los cambios manualmente
-- Ejemplo: Revertir adición de tabla
DROP TABLE IF EXISTS notifications;

-- Ejemplo: Revertir adición de columna
ALTER TABLE places DROP COLUMN IF EXISTS tiktok;

-- Ejemplo: Revertir cambio de tipo
ALTER TABLE places ALTER COLUMN phone TYPE VARCHAR(50);

# 3. Eliminar registro de migración
DELETE FROM _prisma_migrations 
WHERE migration_name = '20260629160000_add_notifications_table';

# 4. Verificar estado
npx prisma migrate status
```

### Script de Rollback Helper

```bash
#!/bin/bash
# scripts/rollback-migration.sh

MIGRATION_NAME=$1

if [ -z "$MIGRATION_NAME" ]; then
    echo "Uso: ./rollback-migration.sh <migration_name>"
    echo "Ejemplo: ./rollback-migration.sh 20260629160000_add_notifications_table"
    exit 1
fi

echo "⚠️  ADVERTENCIA: Esto revertirá la migración $MIGRATION_NAME"
echo "Presione Ctrl+C para cancelar, o Enter para continuar..."
read

# Buscar archivo de rollback
ROLLBACK_FILE="prisma/migrations/${MIGRATION_NAME}/rollback.sql"

if [ ! -f "$ROLLBACK_FILE" ]; then
    echo "❌ No se encontró archivo de rollback: $ROLLBACK_FILE"
    echo "Cree el archivo manualmente antes de ejecutar el rollback."
    exit 1
fi

echo "Ejecutando rollback..."
psql $DATABASE_URL -f "$ROLLBACK_FILE"

echo "Eliminando registro de migración..."
psql $DATABASE_URL -c "DELETE FROM _prisma_migrations WHERE migration_name = '$MIGRATION_NAME';"

echo "Verificando estado..."
npx prisma migrate status

echo "✅ Rollback completado"
```

### Convención: Archivos de Rollback

Para cada migración, crear un archivo `rollback.sql` en el mismo directorio:

```
prisma/migrations/
├── 20260626120000_initial_schema/
│   ├── migration.sql
│   └── rollback.sql          ← Reverso de la migración
├── 20260629160000_add_notifications_table/
│   ├── migration.sql
│   └── rollback.sql          ← DROP TABLE notifications;
```

## 6. Migraciones en CI/CD (GitHub Actions)

```yaml
# .github/workflows/deploy.yml (fragmento)

jobs:
  migrate:
    runs-on: ubuntu-latest
    needs: test
    environment: production
    
    steps:
      - uses: actions/checkout@v4
      
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      
      - run: npm ci
      
      - name: Verificar estado de migraciones
        run: npx prisma migrate status
        env:
          DATABASE_URL: ${{ secrets.DATABASE_URL }}
      
      - name: Aplicar migraciones pendientes
        run: npx prisma migrate deploy
        env:
          DATABASE_URL: ${{ secrets.DATABASE_URL }}
      
      - name: Generar Prisma Client
        run: npx prisma generate
      
      - name: Verificar schema
        run: npx prisma db pull --print
        env:
          DATABASE_URL: ${{ secrets.DATABASE_URL }}
```

## 7. Migraciones para Entornos Específicos

### Desarrollo Local

```bash
# .env.development
DATABASE_URL="postgresql://postgres:postgres@localhost:5432/bolivia_experience_dev"
```

```bash
# Crear migración + aplicar
npx prisma migrate dev --name <nombre>

# Resetear DB (¡destruye datos!)
npx prisma migrate reset

# Ver estado
npx prisma migrate status
```

### Testing

```bash
# .env.test
DATABASE_URL="postgresql://postgres:postgres@localhost:5432/bolivia_experience_test"
```

```bash
# Aplicar migraciones a DB de test
npx prisma migrate deploy

# Seed de datos de test
npx prisma db seed
```

### Staging

```bash
# .env.staging
DATABASE_URL="postgresql://user:pass@staging-host:5432/bolivia_experience"
```

```bash
# Solo deploy (no crear)
npx prisma migrate deploy
```

### Producción

```bash
# .env.production
DATABASE_URL="postgresql://user:pass@prod-host:5432/bolivia_experience"
```

```bash
# Deploy con verificación previa
npx prisma migrate status
npx prisma migrate deploy
npx prisma migrate status
```

## 8. Estrategia de Datos de Prueba (Separada de Migraciones)

Las migraciones manejan **estructura** (DDL), no **datos** (DML).

Los datos iniciales y de prueba se manejan via **Prisma Seed** (ver sub-entregable 4.6).

```json
// package.json
{
  "prisma": {
    "seed": "ts-node prisma/seed.ts"
  }
}
```

## 9. Monitoreo de Migraciones

### Tabla de Registro

Prisma crea automáticamente la tabla `_prisma_migrations`:

```sql
SELECT 
    id,
    checksum,
    migration_name,
    started_at,
    finished_at,
    applied_steps_count,
    logs
FROM _prisma_migrations
ORDER BY started_at DESC;
```

### Alertas

| Condición | Severidad | Acción |
|-----------|-----------|--------|
| Migración fallida | CRÍTICA | Rollback manual + notificación |
| Migración > 5 min | WARNING | Investigar locks o datos grandes |
| Migraciones pendientes en deploy | INFO | Verificar antes de deploy |
