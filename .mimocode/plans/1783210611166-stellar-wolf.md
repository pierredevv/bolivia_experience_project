# Plan: Merge de ramas main y develop

## Contexto

- **main** se trabajó en Flutter + API (seguridad, Google Maps, Admin/Empresa, tests)
- **develop** se trabajó independientemente en Web + CI/CD + Landing + más tests
- Ambas ramas tienen trabajo valioso que debe preservarse
- Objetivo: consolidar en main y continuar allí

## Estrategia

**Merge develop INTO main** con resolución cuidadosa de conflictos.

### Proceso

1. `git checkout main && git pull origin main`
2. `git merge origin/develop`
3. Resolver conflictos preservando trabajo de ambas ramas
4. Commit y push

### Conflictos Esperados y Resolución

| Archivo | main | develop | Resolución |
|---------|------|---------|------------|
| `api/src/app.module.ts` | Admin/Empresa modules | Imports modificados | Combinar ambos |
| `api/src/main.ts` | CORS + Swagger fixes | Cambios generales | Mantener fixes de main |
| `api/src/modules/auth/auth.service.ts` | JWT dual fix | Más cambios | Verificar fixes se mantienen |
| `web/src/App.tsx` | ProtectedRoute básico | ProtectedRoute completo | Usar develop |
| `handoff.md` | Actualizado | Actualizado | Mantener versión más completa |
